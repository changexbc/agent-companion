# 前端迁移至 React + shadcn/ui + TypeScript

## 目标与用户价值
将现有独立 Agent Companion 前端迁移为可维护的 React + TypeScript 界面，按需使用 shadcn/ui 标准控件。降低状态与 DOM 手工同步成本，同时保留当前外观、会话规则、动画和 Tauri 桌面行为。

## 授权与状态
- 用户于 2026-09-22 要求编写 Trellis 计划，准备交给 DeepSeek 改写。
- 本任务仅完成规划，状态为 planning；未授权本轮实施，未执行 task.py start。
- 后续执行者读取最终计划后，由用户明确授权实施再进入 Phase 2。

## 已确认现状
- Vite 多 HTML 入口：desktop.html 与 desktop-settings.html；原生壳为 Tauri，采集运行时为 Rust。
- desktop、welcome、monitor 下现有 JS 约 1,374 行，不含 CSS、HTML、settings-config.js、collector 和测试；行数不等于迁移难度。
- rail.js 汇集 DOM、卡片、菜单、原生命中区域与订阅；设置页包含加载、保存、重试和部分成功反馈。
- 部分 src 模块同时供 Node collector / 测试 / QA 脚本直接加载，必须保留跨运行时兼容。
- 当前没有前端 package spec；已有 Rust spec 索引仍是初始化模板。以研究文件列出的实际代码与测试为行为依据，不把模板视为已验证约定。

## 非目标
不重写 Rust/Hook/collector 协议，不改变通知策略、设置 schema 或存储目录，不增加 3D、路由框架、全局状态库、网络服务和新产品功能。不调整旧办公室/WB Switch 集成，不发布、推送或删除历史资产。不要求 collector、scripts 和 tests 全部改成 TS。

## 验收标准
- AC1（R1–R2）：两个入口 dev/build 可用；新增 typecheck 与 lint 通过；前端迁移完成，没有通过全局 any、ts-nocheck 或排除业务目录绕过类型检查。共享 JS 例外有检查且有明确清单。
- AC2（R3、R6）：设置全部现有控件可键盘操作；读/写失败和部分成功信息准确；保存与重启后持久化正确；scene 等未展示分组及 source.path 不被覆盖；原生开机自启与浏览器不支持态保持。
- AC3（R4–R5）：现有模型断言不降低；running→wait→done 与断连恢复正常；wait 静音按轮次/问题清除，done 无自动卡；头像及动画与基线一致。
- AC4（R7）：真实 macOS 应用可拖动、点击穿透、非激活悬停、点击菜单/卡片及关闭设置；弹层出现/移动/消失后命中区域及时更新；卸载/重复挂载无多余订阅和残留动画。
- AC5（R8）：Node、Rust parity、UI、runtime、bundle、native-app 检查通过；测试选择器允许适配 React 控件语义，但不得删除对应业务断言。
- AC6（R5、R8）：提交迁移前后截图及资源数据，人工视觉确认单独记录；自动截图不等于人工验收。无法测量的原生性能或人工项必须标为未验证，不能宣布全部完成。

## 决策与待验证事项
目标范围已明确，无阻塞规划的产品问题。实施前需核实依赖版本、Node 共享模块传递依赖清单和本机原生 QA 能力；均不得以此扩大产品范围。性能没有人为预设提升目标，使用同机同场景对照，出现可重复回归需定位并在交付中披露。
